# CupAI 数据源系统性分析与获取方案

> 范围：除**舆情数据**（用户/系统主动提交后由自研情感分析引擎处理）和**用户主动添加的数据**（用户、AI 配置、Prompt 模板、分析报告、互动评论）之外的所有其他数据源。
> 文档版本：v1.0（2026-06-05）

---

## 一、执行摘要

通过对 `apps/server/src/modules/**` 全量代码与 `deploy/init.sql` 种子脚本的逐项审计，**当前系统内不存在运行时外部数据拉取通道**。所有"非舆情、非用户主动"的数据全部来自：

1. **种子数据**（`deploy/init.sql`，Docker 启动时一次性注入）—— 球队、球员、赛事、积分榜、敏感词、默认 Prompt
2. **派生数据**（基于基础数据 + 自研算法运算）—— 积分榜、出线概率、情感得分、权重处理结果
3. **缓存数据**（Redis，TTL 自动失效）—— 比赛列表、球队列表、舆情聚合
4. **系统级 AI 调用**（`@Cron` 定时 + 用户/系统配置的 LLM）—— Agent 自动分析报告

`.env` 中保留的 `DATA_SYNC_INTERVAL=60`、`SENTIMENT_SYNC_INTERVAL=30` **是孤儿配置**（无对应实现），属于历史遗留或为后续对接外部数据源预留的钩子。

## 三、各数据源详细方案

### DS-01 球队基础信息

- **当前获取途径**：`deploy/init.sql` 静态 INSERT（16 支示例球队）
- **技术实现**：SQL DDL/DML，无运行时同步
- **更新频率**：仅 Docker 启动时一次
- **数据质量评估标准**：
  - 完整度：球队字段必填项覆盖率 ≥ 100%
  - 时效性：FIFA 排名更新延迟 ≤ 30 天
  - 一致性：球队 ID 与外部权威源（FIFA/transfermarkt）一致
- **API/访问权限**：无（暂未对接）
- **稳定性/可靠性**：完全依赖种子脚本，无法运行时更新
- **合规性**：FIFA 数据属公开信息，无授权问题
- **建议升级方案**：
  - 接入 **API-Football**（api-football.com）作为权威源，需 API Key（免费层 100 req/day）
  - 或 **football-data.org**（免费版 10 req/min，无商业授权）
  - 在 `apps/server/src/modules/match/` 下新增 `TeamSyncService`，实现 `TeamProvider` 抽象，支持多 provider 切换
  - Cron `0 2 * * 1`（每周一凌晨 2 点）触发增量同步

### DS-02 球员基础信息

- **当前获取途径**：`deploy/init.sql`（10 名核心球员）
- **技术实现**：静态 INSERT
- **更新频率**：一次性
- **数据质量评估标准**：
  - 伤病状态准确度（影响分析报告）
  - 进球/助攻数据延迟 ≤ 7 天
  - 关键球员（`is_key_player`）识别准确度
- **API/访问权限**：无
- **稳定性/可靠性**：球员状态陈旧，影响"球员状态分析" Prompt 输出
- **合规性**：FIFA/联赛官方数据可商用需授权
- **建议升级方案**：
  - 接入 **API-Football** `/players?team={id}&season=2026`
  - 或自建爬虫抓取 whoscored.com、transfermarkt（注意 robots.txt）
  - 实现 `PlayerSyncService`，按球队 ID 批量拉取并 UPSERT

### DS-03 赛事日程

- **当前获取途径**：`deploy/init.sql`（8 场小组赛示例）
- **技术实现**：静态 INSERT
- **更新频率**：一次性
- **数据质量评估标准**：
  - 开赛时间准确度（影响 Agent 调度）
  - 场馆/裁判信息完整度
  - 阶段（小组赛/淘汰赛）准确度
- **API/访问权限**：无
- **稳定性/可靠性**：仅 8 场示例，远不足以支撑完整赛事
- **合规性**：FIFA 赛程公开
- **建议升级方案**：
  - 接入 **API-Football** `/fixtures?league=1&season=2026`
  - 实现 `MatchSyncService`，按 league/season 拉取全量赛程
  - 支持 schedule_update webhook，接收官方赛程变更推送

### DS-04 小组积分（派生）

- **当前获取途径**：`StandingService.updateStandings(matchId)`，由 `MatchEntity` 计算
- **技术实现**：`win*3 + draw*1` 标准积分规则
- **更新频率**：依赖赛事状态更新（`status: 'finished'`）
- **数据质量评估标准**：
  - 积分与比赛结果一致性 100%
  - 净胜球、进球数、胜平负数正确性
- **API/访问权限**：无（纯派生）
- **稳定性/可靠性**：✅ 高（基于确定性算法）
- **合规性**：N/A
- **建议升级方案**：
  - 现状已满足需求
  - 可选：在 `match.status` 变更时（管理员手动/API webhook）自动触发，避免遗漏

### DS-05 球队 FIFA 排名

- **当前获取途径**：`teams.fifa_rank` 字段静态值
- **技术实现**：种子数据
- **更新频率**：FIFA 官方每月更新一次
- **数据质量评估标准**：与 FIFA 最新排名一致
- **API/访问权限**：FIFA Connect API（需付费授权）
- **稳定性/可靠性**：低（依赖人工维护）
- **合规性**：FIFA 数据再分发需授权
- **建议升级方案**：
  - **低成本方案**：接入 **API-Football** `/rankings/fifa`（已包含）
  - **中成本方案**：FIFA Connect Partner Program（年费 USD 5K+）
  - **推荐方案**：API-Football 月度同步

### DS-06 赛事环境数据（天气/场馆/裁判）

- **当前获取途径**：`matches` 表的 `temperature/humidity/weather_condition/wind_speed/referee_*` 字段
- **技术实现**：种子数据
- **更新频率**：一次性
- **数据质量评估标准**：
  - 比赛当天天气准确度（影响战术分析）
  - 裁判风格识别准确度
- **API/访问权限**：
  - 天气：OpenWeatherMap（免费 1000 req/day）/ Open-Meteo（免费无限）
  - 裁判：FIFA 官方 / 联赛官方
- **稳定性/可靠性**：低（种子数据多为猜值）
- **合规性**：天气 API 商用需订阅
- **建议升级方案**：
  - 比赛前 6 小时自动拉取 Open-Meteo（无授权）+ 解析 venue 坐标
  - 裁判信息维护人工 + 联赛官方推送

### DS-07 敏感词库

- **当前获取途径**：`deploy/init.sql`（8 个赌博类敏感词）
- **技术实现**：静态 INSERT
- **更新频率**：一次性
- **数据质量评估标准**：
  - 覆盖率（赌博/歧视/政治/暴力等类别）
  - 误判率 < 5%
- **API/访问权限**：无
- **稳定性/可靠性**：✅ 高（人工维护简单）
- **合规性**：✅ 中国《网络安全法》《互联网信息服务管理办法》合规
- **建议升级方案**：
  - 现状已满足基本需求
  - 建议增加分类管理（gambling/political/discriminatory/violent）
  - 接入第三方词库（如阿里云内容安全 SDK，0.01 元/次）

### DS-08 默认 Prompt 模板

- **当前获取途径**：`deploy/init.sql`（5 个内置模板）
- **技术实现**：种子数据，`user_id='system'`
- **更新频率**：一次性
- **数据质量评估标准**：
  - 模板可执行性（含必需变量）
  - 输出质量（人工抽检）
- **API/访问权限**：无
- **稳定性/可靠性**：✅ 高
- **合规性**：N/A
- **建议升级方案**：
  - 现状已满足需求
  - 建议支持运行时通过管理后台更新 system prompt（V1.4+ 规划）

### DS-09 Agent 自动分析报告

- **当前获取途径**：`AgentSchedulerService.scanUpcomingMatches` 调用 `AiService.proxyAiRequest`
- **技术实现**：
  ```typescript
  @Cron('*/30 * * * *')  // 每 30 分钟
  // 调用系统 LLM（环境变量 AGENT_AI_ENDPOINT / AGENT_AI_KEY / AGENT_AI_MODEL）
  ```
- **更新频率**：每 30 分钟
- **数据质量评估标准**：
  - 分析内容长度（建议 ≥ 500 字）
  - 引用数据准确度（不编造球队/球员）
  - 用户反馈评分（点赞/踩）
- **API/访问权限**：
  - DeepSeek API（`https://api.deepseek.com/v1`，免费额度）
  - OpenAI API（付费）
  - 火山方舟/通义千问（中文优化）
- **稳定性/可靠性**：中（依赖第三方 LLM 稳定性）
- **合规性**：
  - LLM 输出内容需经过风险审核（已实现 `RiskService.reviewAiContent`）
  - 避免生成赌博诱导、政治敏感内容
- **建议升级方案**：
  - 多 LLM 灾备：主用 DeepSeek，备用 GPT-4o-mini
  - 实现 prompt 模板 A/B 测试
  - 增加 LLM 调用预算控制（每日最大 token 数）

### DS-10 ~ DS-12 缓存层

- **当前获取途径**：`MatchCacheService` / `SentimentService` 读写穿透
- **技术实现**：Redis + TTL
- **更新频率**：TTL 到期自动失效
- **数据质量评估标准**：
  - 缓存命中率（应 > 80%）
  - 缓存失效延迟（应 < 1 min）
- **API/访问权限**：无
- **稳定性/可靠性**：✅ 高
- **合规性**：N/A
- **建议升级方案**：
  - 现状已满足需求
  - 建议增加 `match:detail:{id}` 缓存（详情页高频访问）

### DS-13 用户 AI 配置

- **当前获取途径**：`POST /api/v1/ai/config` 用户提交
- **技术实现**：MySQL 存储配置（apiEndpoint/temperature/maxTokens），API Key **不入库**
- **更新频率**：用户主动
- **数据质量评估标准**：
  - API Key 仅前端加密存储（当前是临时传入，零持久化）—— **最佳实践**
- **API/访问权限**：用户自配
- **稳定性/可靠性**：✅ 高
- **合规性**：✅ API Key 不经过服务端，规避密钥泄露风险
- **建议升级方案**：保持现状

### DS-14 比赛实时比分

- **当前获取途径**：`AgentSchedulerService.checkLiveMatches`（每 5 分钟），`MatchEntity.homeScore/awayScore` 字段
- **技术实现**：数据库读取 + WebSocket 广播
- **更新频率**：每 5 分钟
- **数据质量评估标准**：
  - 比分变化推送延迟 ≤ 30 秒（当前 5 min 远不够）
- **API/访问权限**：无（依赖人工/管理员更新）
- **稳定性/可靠性**：中（比分陈旧）
- **合规性**：N/A
- **建议升级方案**：
  - **关键升级**：管理员后台手动更新比分（V1.4 规划）
  - 或接入 **API-Football** Live 通道（`/fixtures?live=all`，WebSocket 推送）
  - 或接入 **Sportradar**（专业体育数据，年费 USD 10K+）

## 四、稳定性、可靠性、合规性综合评估

### 4.1 稳定性等级

| 等级 | 数据源 | 风险点 |
|---|---|---|
| 🟢 高 | DS-04, DS-07, DS-08, DS-10~13 | 派生/纯本地/用户主动 |
| 🟡 中 | DS-09 | 依赖第三方 LLM，可用性 99.5% |
| 🟠 偏低 | DS-01~03, DS-05, DS-06, DS-14 | 种子数据陈旧，无外部同步 |

### 4.2 合规性风险

- ✅ **无版权风险**：FIFA/联赛公开数据 + 用户自配 API Key
- ✅ **数据本地化**：所有数据存储在自有 MySQL，不出境
- ✅ **隐私保护**：用户 AI Key 零持久化
- ⚠️ **LLM 输出审核**：需确保所有 AI 生成内容经过 `RiskService` 过滤
- ⚠️ **境外 LLM 限制**：生产环境建议使用国内 LLM（DeepSeek/通义）规避出境合规

### 4.3 可靠性改进路线图


```typescript
@Injectable()
export class DataSyncScheduler {

    const teams = await this.provider.fetchTeams()
    await this.upsertTeams(teams)
    this.logger.log(`已同步 ${teams.length} 支球队`)
  }

  @Cron('0 2 * * *')  // 每天凌晨 2 点
  async syncMatches() {
    // 拉取最近 7 天赛程
  }

  @Cron(CronExpression.EVERY_6_HOURS)  // 每 6 小时
  async syncWeather() {
    // 拉取未来 24 小时内开赛的比赛天气
  }
}
```

### 5.3 降级与告警

- **多 provider 灾备**：API-Football 失败 → 自动 fallback football-data.org
- **同步失败告警**：连续 3 次同步失败 → 飞书/钉钉机器人告警
- **数据陈旧告警**：基础数据 30 天未更新 → 警告标记

## 七、总结

**当前系统数据源策略是"种子数据 + 派生 + 用户主动"三件套**，**没有运行时外部数据拉取**。这种架构优点是简单、合规风险低；缺点是数据陈旧、覆盖不全。

**建议优先级**：
1. **P0（立即）**：清理 `.env` 孤儿配置 + 文档化（本文档）
2. **P1（1 个月内）**：接入 Open-Meteo 天气同步、比分管理后台
3. **P2（3 个月）**：接入 API-Football 免费层（球队/球员/赛程）
4. **P3（6 个月+）**：实现统一 `DataSourceProvider` 抽象层，付费数据源接入

**核心指标建议**：
